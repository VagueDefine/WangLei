# Git Reset 三种模式完全指南

## 🚀 快速选择（复制即用）

| 需求                | 命令                        | 危险等级  |
| :---------------- | :------------------------ | :---: |
| **保留代码，重新提交**（推荐） | `git reset --soft HEAD^`  | 🟢 安全 |
| **保留代码，继续编辑**（默认） | `git reset --mixed HEAD^` | 🟢 安全 |
| **彻底删除，不要代码**     | `git reset --hard HEAD^`  | 🔴 危险 |

---

## 📊 三种模式深度对比

| 命令                        |   工作区    |     暂存区     |  提交历史  | 适用场景              |
| :------------------------ | :------: | :---------: | :----: | :---------------- |
| `git reset --soft HEAD^`  |   ✅ 保留   | ✅ **保留已暂存** | ⏪ 回退1步 | 修改提交信息、漏加文件、合并提交  |
| `git reset --mixed HEAD^` |   ✅ 保留   | ❌ **取消暂存**  | ⏪ 回退1步 | 拆分提交、继续编辑、重新选择文件  |
| `git reset --hard HEAD^`  | ❌ **丢弃** |  ❌ **清空**   | ⏪ 回退1步 | 彻底放弃错误代码（⚠️ 不可恢复） |

---

## 🔧 模式详解

### 1. --soft：安全回退（⭐ 最推荐）

```bash
git reset --soft HEAD^
```

**效果示意图：**
```
执行前                执行后
┌─────────┐          ┌─────────┐
│  工作区  │    →     │  工作区  │  ← 无变化
│ (干净)  │          │ (干净)   │
├─────────┤          ├─────────┤
│  暂存区  │    →     │ ←有改动→│  ← 变更保留在暂存区
│ (干净)  │          │ (已暂存)│
├─────────┤          ├─────────┤
│  HEAD   │    →     │  HEAD^  │  ← 回退1步
│(上次提交)│          │(上上次)  │
└─────────┘          └─────────┘
```

**特点：**
- 撤销最后一次提交
- 所有变更保留在**暂存区**（`git status` 显示绿色）
- 工作区文件完全不动

**适用场景：**
- 提交信息写错了，想重新写
- 漏加了文件，想合并到上一次提交
- 想把多个小提交合并成一个

**后续操作：**
```bash
# 直接修改提交信息后重新提交
git commit -m "修正后的提交信息"

# 或漏加文件后一起提交
git add 漏加的文件
git commit -m "补充提交"
```

---

### 2. --mixed：灵活回退（默认模式）

```bash
git reset --mixed HEAD^
# 简写形式（效果相同）
git reset HEAD^
```

**效果示意图：**
```
执行前                执行后
┌─────────┐          ┌─────────┐
│  工作区  │    →     │ ←有改动→│  ← 变更退回工作区
│ (干净)  │          │ (未暂存)│
├─────────┤          ├─────────┤
│  暂存区  │    →     │  暂存区  │  ← 清空
│ (干净)  │          │ (干净)  │
├─────────┤          ├─────────┤
│  HEAD   │    →     │  HEAD^  │
│(上次提交)│          │(上上次) │
└─────────┘          └─────────┘
```

**特点：**
- 撤销最后一次提交
- 变更退回**工作区**（`git status` 显示红色，未暂存）
- 需要重新 `git add` 才能提交

**适用场景：**
- 提交后发现还有要修改的地方
- 想拆分上一次提交的多个文件（部分提交）
- 不确定要不要保留所有变更，先放工作区筛选

**后续操作：**
```bash
# 选择性添加文件重新提交
git add 文件1 文件2
git commit -m "新的提交信息"

# 或继续修改后再提交
vim 某个文件
git add .
git commit -m "修改后的提交"
```

---

### 3. --hard：彻底重置（⚠️ 极度危险）

```bash
git reset --hard HEAD^
```

**效果示意图：**
```
执行前                执行后
┌─────────┐          ┌─────────┐
│  工作区  │    →     │  工作区  │  ← 强制还原
│ (干净)  │          │ (干净)  │
├─────────┤          ├─────────┤
│  暂存区  │    →     │  暂存区  │  ← 清空
│ (干净)  │          │ (干净)  │
├─────────┤          ├─────────┤
│  HEAD   │    →     │  HEAD^  │
│(上次提交)│          │(上上次) │
└─────────┘          └─────────┘
```

**⚠️ 警告：**
- **变更不可恢复！** 除非使用 `git reflog` 且未过期
- 远程协作时绝对不要用（会丢失团队代码）

**适用场景：**
- 确定上一次提交完全是错误的实验代码
- 想完全放弃当前所有未提交/已提交的修改
- 清理工作区回到干净状态

## 🛠️ 补充常用命令

### 查看版本历史（找版本号）

```bash
# 简洁视图
git log --oneline

# 输出示例：
# a1b2c3d (HEAD -> main) 错误的提交
# e5f6g7h 上一个正确的版本
# i8j9k0l 更早的版本
```

### 回退到指定版本

```bash
# 软回退到指定版本
git reset --soft e5f6g7h

# 硬回退到指定版本（⚠️ 危险）
git reset --hard e5f6g7h
```

### 强制推送到远程仓库

```bash
# ⚠️ 只有你自己用的分支才能执行！
git push -f origin 你的分支名

# 或完整写法
git push --force origin main
```

---

## 🆘 后悔药：数据恢复

即使使用了 `--hard`，也能找回（只要没过期）：

```bash
# 查看所有操作记录（包括被reset的提交）
git reflog

# 找到被删除提交的版本号，例如 a1b2c3d
git reset --hard a1b2c3d  # 恢复该提交
```

## 🎯 决策流程图

```
需要撤销最后一次提交？
    │
    ├── 想保留代码，只改提交信息？
    │   └── git reset --soft HEAD^
    │
    ├── 想保留代码，但重新选择提交内容？
    │   └── git reset --mixed HEAD^（或直接 git reset HEAD^）
    │
    └── 确定代码完全错误，一点都不要？
        └── git reset --hard HEAD^ ⚠️ 先确认真的不要了！
```

---

## 💡 安全建议

1. **优先使用 `--soft`** —— 给了自己反悔的余地
2. **hard 之前先备份** —— 或者至少看一眼 `git diff HEAD^`
3. **远程分支别用 hard + force** —— 队友会打人
4. **记住 reflog** —— 终极后悔药
5. **不确定时用 `--soft`** —— 进可攻退可守
